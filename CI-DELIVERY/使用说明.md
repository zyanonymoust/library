## 文件内容

- files/Library.API/ApiAssemblyMarker.cs：让集成测试找到 API 所在程序集。
- files/Library Tests/Library Tests.csproj：增加 API 项目引用和 WebApplicationFactory 测试依赖。
- files/Library Tests/LibraryApiFactory.cs：启动真实 API，每个测试使用独立的 SQLite 内存数据库，保留实际数据库迁移过程。
- files/Library Tests/ApiIntegrationTests.cs：10 个 HTTP 测试用例，覆盖创建图书、下单扣库存、超库存、无效数量、无效 ID、空标题和删除后的行为。
- files/.github/workflows/dotnet-tests.yml：每次 push 或 PR 自动还原依赖、编译、测试并保存 TRX 报告。
- files/README.md：保留原有 API 文档，补充测试和 CI 说明。
- files/docs/CI-SUBMISSION.md：验证过程、证据状态和截图清单。

## 如何应用

1. 在 Visual Studio 中先保存当前修改，并创建新分支，例如 codex/integration-tests-ci。
2. 把 files 文件夹里面的内容复制到仓库根目录，保持目录结构。README.md 和测试项目文件会替换同名文件，请先比较本地是否有尚未提交的修改。
3. 在仓库根目录运行 dotnet test library.slnx。需要 .NET 10 SDK。
4. 成功后提交并推送新分支，到 GitHub 的 Actions 页面检查运行情况。预期总数为 17 个测试，实际结果以运行报告为准。
5. 按 CI-SUBMISSION.md 临时把库存断言从 8 改成 9，提交并推送，确认失败原因确实是断言失败。
6. 保存红色失败截图，然后恢复为 8，再次提交并推送，保存绿色成功截图。

## 截图应包含什么

绿色截图：仓库名称、提交、工作流成功状态、测试结果。

红色截图：失败的 Test 步骤、失败测试名称、Expected 9 / Actual 8 和失败退出信息。

如果要求禁止合并失败的代码，还需要管理员在 main 分支规则中要求 Build and test 检查通过。工作流变红本身不代表已经禁止合并。
