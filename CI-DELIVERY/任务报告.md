## 3. 准备的实现

### 集成测试环境

LibraryApiFactory 继承 WebApplicationFactory<ApiAssemblyMarker>，启动 API 所在程序集。测试保留实际控制器、BookService、EfBookRepository、Entity Framework Core 和启动时的数据库迁移。

仅将数据库注册替换为 SQLite 内存数据库。每个测试实例使用独立连接，在测试结束后释放，因此测试不会修改项目的 bookstore.db 文件，也不会依赖先前测试的数据。

测试客户端使用 https://localhost 并关闭自动重定向，通过 HttpClient 访问真实应用路由。这里的服务器是进程内测试服务器，不需要手动启动一个外部 API 服务。

### GitHub Actions

工作流文件为 .github/workflows/dotnet-tests.yml。触发条件为每次 push 和 pull_request，没有分支或路径过滤。

步骤依次为检出代码、安装 .NET 10 SDK、还原依赖、Release 编译、运行 dotnet test，以及上传 TRX 测试报告。

测试命令没有 continue-on-error 或忽略退出码的逻辑。报告上传步骤使用 always()，用于在测试失败后尽可能保存结果，不会把失败的测试步骤改为成功。

## 4. 本地执行方法

先按照使用说明.md 将 files 中的文件应用到仓库对应位置，再在仓库根目录执行：

```powershell
dotnet restore library.slnx
dotnet build library.slnx --configuration Release --no-restore
dotnet test library.slnx --configuration Release --no-build --logger "trx;LogFileName=tests.trx" --results-directory TestResults
```

如有失败，应先检查还原、编译或断言输出，修复后再提交。不要将工具或依赖错误当作故意断言失败的证据。
